Background of Data Flow Diagrams

Due to Ed Yourdon and Larry Constantine's book Structured Design, which was written in the late 1970s, data flow diagrams became widely used. They used David Martin and Gerald Estrin's "data flow graph" computation models as its foundation. In the world of software engineering, the structured design concept and DFD methodology have gained popularity as it was used for business analysis.

Common Symbols Involved
External Entity is a outside system that sends or recieves data, they can represent a person, organization or a computer system

A process is anything that performs algorithsm on incoming data and produces a output which can be stored, go through another process or back to a external entity

Data store holds the data for using in the future and can have name tags like “reserved rooms”

Data flow uses arrows to show the direction of the data which can flow through all the other components. They can have name tags like “username”
Types of DFD
From the diagram on the left you can see that there are different Data Flow Diagrams symbols and it is essential to identify them from the different categories so you dont get confused when working with them
Level 0

Level 0 aka context diagram Presents a basic overview of the system and can be easily understood by anyone, Doesnt really contain any indepth info on the processes.

Level 1

Level 1 shows a bit more detail compared to level 0; it breaks down high level processes with sub processes

Level 2

Level 2 goes into much more detail compared to level 1 and requires more symbols in general which may be substantial enough to preview a base level system. Level 3 is goes in more detail compared to level 2, breaks down a lot of subprocesses into more subprocesses with addition to more symbols used. Any level above 3 ican cause many issues since it can get complex very quick and modelling can be a issue

Logical Vs Physical DFD's

Now before you make your actual Data Flow diagram you must conisder whether it is either a Logical or Physical Diagram. A logical digaram represents a system which is essential for a business to opernate, not necesserily how it should work as opposed to physical diagrams which look at the processes and procedures (behind the scenes) of how the business should operate.
